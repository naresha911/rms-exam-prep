# AISSEE Student Preparation App

## Client Application Requirements — MVP + Future Roadmap

**Project:** All India Sainik Schools Entrance Examination (AISSEE) Preparation Platform
**Target Students:** Students currently studying in Class 5 and Class 8
**Target Admission:** Class 6 and Class 9 respectively
**Platform:** Android first, iOS/web-ready architecture
**Status:** Living product requirements (aligned with codebase where noted)

**Doc index:** see [`README.md`](README.md) in this folder. Feature deep-dives (e.g. Previous Papers) live in dedicated specs and override older short sections when linked.

---

# 1. Product Vision

Build a fun, structured and highly engaging learning application that helps students prepare for the **All India Sainik Schools Entrance Examination (AISSEE)**.

The application should not feel like a traditional exam-preparation website converted into a mobile app.

It should feel like a **personal Sainik School preparation companion**.

The experience should combine:

* Structured learning
* Topic-wise practice
* Daily practice
* Mock examinations
* Previous-year papers
* Performance analysis
* Gamification
* Revision
* Personalized recommendations
* Friendly AI-assisted explanations in future
* Parent visibility in future

The application should be suitable for children around the Class 5/Class 8 age group and therefore prioritize **simplicity, motivation, clarity and low cognitive load**.

---

# 2. Product Positioning

### Proposed positioning

> **"Your personal Sainik School preparation companion."**

The application should help a student answer three questions every day:

1. **What should I learn today?**
2. **How well am I performing?**
3. **What should I improve next?**

Instead of simply presenting thousands of questions, the app should progressively guide the student toward exam readiness.

# 34. Previous Year Papers

> **Implementation spec (source of truth):** [`previous-papers.md`](previous-papers.md)  
> **Schema deploy:** [`sql/papers_v1.sql`](sql/papers_v1.sql) · **Verify:** [`papers-verification.md`](papers-verification.md)

Provide a dedicated section in the student app:

### Previous Year Papers

**Browse / filter**

* Target class (from student profile / onboarding — Class 6 or 9)
* Year chips and “Recent”
* Difficulty from `papers.difficulty` when set
* Section summary chips from paper–question mapping

**Per paper**

* **Start Paper** / **Resume** (one in-progress attempt per student per paper)
* Timed session using ordered `paper_questions` (marks + negative marks)
* **Submit** → server-scored **Result** (attempt history / re-attempt)
* Optional **Open official PDF** via private Storage signed URL (`papers.pdf_path`)
* Offline resume for cached sessions; answers sync when online

**v1 question types in paper session:** `mcq_single`, `true_false`, `assertion_reason`.

**Not required in v1:** Pro entitlement lock on papers/PDF; push notifications for newly published papers; full subject filter UI beyond section chips.

Past papers remain a high-value content category; entitlement gating can be added later without changing the attempt model.

# 54. Advertising

Because the target audience is children, advertising should **not be the primary monetization mechanism**.

Recommended:

* No intrusive ads during an examination
* No misleading advertisements
* No ads disguised as educational content
* No ads affecting question selection
* Prefer subscription/freemium monetization

Any advertising strategy should be reviewed against applicable child-safety/privacy requirements before implementation.

Competitors already advertise thousands of MCQs, structured levels, videos, mock tests, leaderboards and performance tracking.

Instead, our differentiation should be:

> **"We tell the student exactly what to practice next."**

The product should progressively become a **personal AISSEE coach**.
